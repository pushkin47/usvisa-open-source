# Развертывание и настройка US Visa Open Source для Астаны

> **ВАЖНО: АВТОР НЕ ПОДДЕРЖИВАЕТ И НЕ ОДОБРЯЕТ ИСПОЛЬЗОВАНИЕ АВТОМАТИЗИРОВАННЫХ СРЕДСТВ ДЛЯ ВОЗДЕЙСТВИЯ НА РАБОТУ САЙТОВ ПОСОЛЬСТВ, КОНСУЛЬСТВ И ВИЗОВЫХ СИСТЕМ ЛЮБЫХ СТРАН, ВКЛЮЧАЯ США. ПУБЛИКАЦИЯ ПРОЕКТА НЕ ЯВЛЯЕТСЯ ПРИЗЫВОМ К ТАКОМУ ИСПОЛЬЗОВАНИЮ. СОБЛЮДАЙТЕ ПРАВИЛА И ОГРАНИЧЕНИЯ СООТВЕТСТВУЮЩИХ СЕРВИСОВ.**

Эта инструкция проводит от скачивания проекта до первой проверки свободных дат и постоянной работы сервиса. Основной сценарий: один человек устанавливает приложение для своего аккаунта AIS. В конце описаны несколько пользователей, сервер Linux, резервная копия и типичные ошибки.

Приложение поддерживает только Астану, ID консульства `134`. Оно умеет проверять даты и время, показывать результаты в локальной веб-панели и автоматически записывать на выбранные приоритетные даты. Внешних уведомлений и почтовых рассылок нет. Пустой приоритетный список оставляет только мониторинг.

## 1. Какие сайты и учетные записи понадобятся

В процессе используются три разных адреса:

| Адрес | Для чего нужен |
| --- | --- |
| [Визовый раздел посольства США в Казахстане](https://kz.usembassy.gov/visas/) | Официальная информация о визах и действующих правилах подачи |
| [AIS для неиммиграционных виз в Казахстане](https://ais.usvisa-info.com/ru-kz/niv) | Ваш аккаунт, доступ к процедуре записи, страница собеседования |
| [Локальная панель приложения](http://127.0.0.1:8765) | Управление установленным монитором на вашем компьютере |

Сайт посольства и страница записи не являются одним адресом. В поле `Appointment URL` нужен адрес из вашего авторизованного кабинета AIS, который заканчивается на `/schedule/ВАШ_ID/appointment`. Главная страница посольства для этого поля не подходит.

Сам монитор не создает визовую анкету, не оплачивает сбор и не выдает доступ к записи. До настройки откройте AIS обычным браузером, выполните требуемые порталом действия для своего случая и убедитесь, что можете дойти до страницы записи в Астане. Вопросы категории визы, анкеты и оплаты решаются по официальной инструкции посольства и портала.

Названия кнопок и условия доступа на внешнем сайте могут измениться. Приведенные ниже пути соответствуют формату, который поддерживает код приложения; если ваш кабинет показывает другой формат, не подставляйте похожие адреса наугад.

### Два разных пароля

| Учетная запись | Где используется | Откуда взять |
| --- | --- | --- |
| Администратор локальной панели | Вход на `127.0.0.1:8765` | Email задаете сами в `USVISA_ADMIN_EMAIL`; отдельный пароль создаете сами |
| Аккаунт AIS | Вход в систему записи через браузер | Email и пароль, с которыми вы уже входите на `ais.usvisa-info.com` |

Не используйте пароль AIS для локальной панели. Email администратора не нужно подтверждать по почте: приложение ничего не отправляет. Пароли AIS, cookies и конфигурация должны оставаться на вашей машине или вашем сервере.

## 2. Выберите место установки

**Компьютер с macOS или Linux** удобнее для первого запуска: видны окно Chromium, форма входа и возможные дополнительные проверки сайта. Монитор работает, пока включен компьютер и запущено приложение.

**Сервер Linux** удобен для постоянной работы. Он должен иметь доступ к AIS. На сервере без рабочего стола браузер запускается в headless-режиме, без окна. Если сайт требует интерактивную проверку, потребуется рабочий стол или другой разрешенный ручной способ входа; SSH-туннель к панели сам по себе не показывает окно Chromium.

**Windows** напрямую не поддерживается из-за `fcntl` в коде монитора. Можно использовать Linux через WSL, но WSL и графический режим отдельно в этой версии не проверялись. Все команды далее рассчитаны на shell macOS/Linux.

Для воспроизводимого запуска используйте Python **3.12**. Более новые версии Python этой инструкцией не проверены. Должны быть установлены Git и возможность создать виртуальное окружение Python.

## 3. Подготовьте Python и Git

Откройте терминал:

```bash
python3.12 --version
git --version
```

Первая команда должна вывести `Python 3.12.x`, вторая: версию Git. Если Python вызывается как `python3`, проверьте `python3 --version`: использовать его вместо `python3.12` можно, когда это именно версия 3.12.

Для macOS выберите доступный вам способ установки Python 3.12. Официальные выпуски опубликованы на [python.org](https://www.python.org/downloads/). Если у вас уже установлен Homebrew, можно использовать его пакет `python@3.12`. Не заменяйте системный Python вручную.

На Ubuntu 24.04 Python 3.12 и инструменты для окружения устанавливаются штатными пакетами:

```bash
sudo apt update
sudo apt install python3.12 python3.12-venv git
```

Эти команды относятся именно к Ubuntu с доступными указанными пакетами. Для другой системы используйте ее пакетный менеджер; не добавляйте случайный сторонний репозиторий ради выполнения команды.

## 4. Скачайте проект

Откройте страницу этого репозитория на GitHub. Нажмите **Code**, выберите **HTTPS** и скопируйте адрес репозитория.

В команде ниже замените `REPOSITORY_HTTPS_URL` скопированным адресом. Это обозначение, а не готовая ссылка:

```bash
git clone REPOSITORY_HTTPS_URL usvisa-open-source
cd usvisa-open-source
```

У публичного репозитория скачивание не требует GitHub-токена. Альтернативный вариант: **Code > Download ZIP**, распаковать архив и перейти в распакованный каталог. Установка из ZIP подходит для запуска, но обновлять ее через `git pull` нельзя.

Проверьте содержимое каталога:

```bash
ls
```

Должны быть видны `README.md`, `requirements.txt`, `src` и `tests`. Скрытый файл `.env.example` тоже должен быть в каталоге; его покажет `ls -a`.

Все команды дальнейшей установки выполняйте из корня проекта, рядом с `requirements.txt`.

## 5. Создайте окружение и установите зависимости

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
```

`.venv` содержит отдельный Python и библиотеки только этого проекта. Команда `source .venv/bin/activate` включает это окружение для текущего терминала. После открытия нового терминала сначала вернитесь в каталог проекта и повторите активацию.

Chromium устанавливается отдельно от библиотеки Playwright. Обычный Chrome, который уже стоит на компьютере, не заменяет эту установку. Принцип установки браузеров описан в [документации Playwright](https://playwright.dev/python/docs/browsers).

На Linux при нехватке системных библиотек выполните:

```bash
python -m playwright install --with-deps chromium
```

Эта команда может потребовать права администратора для системных пакетов. На сервере устанавливайте браузер под тем же пользователем, от которого впоследствии будет запущен сервис: браузерные файлы обычно сохраняются в пользовательском кеше.

## 6. Создайте приватный файл настроек

```bash
cp .env.example .env
chmod 600 .env
```

Откройте `.env` текстовым редактором. Для первого запуска панели обязательно заполнить две строки:

```dotenv
USVISA_ADMIN_EMAIL=
USVISA_ADMIN_PASSWORD=
```

После знака `=` введите свой email и придуманный пароль локальной панели. Пароль должен содержать не менее 12 символов. Получить случайный пароль можно командой:

```bash
python -c "import secrets; print(secrets.token_urlsafe(24))"
```

Сохраните результат в менеджере паролей и внесите его в `.env`. В репозитории нет готового администратора или стандартного пароля.

В `.env` используется формат `ИМЯ=значение`, по одной настройке на строку. Значения с пробелами и `#` заключайте в кавычки. Не выполняйте файл `.env` командой `source`: приложение само читает его через `python-dotenv`.

Для первого запуска оставьте:

```dotenv
USVISA_MONITOR_AUTOSTART=false
USVISA_BROWSER_HEADLESS=false
USVISA_VPN_ENABLED=false
USVISA_PRIORITY_DATES=
```

На сервере без рабочего стола вместо `false` у `USVISA_BROWSER_HEADLESS` поставьте `true`. Bootstrap-поля cookie и CSRF пока не заполняйте.

## 7. Получите адреса своего аккаунта AIS

### 7.1. Войдите в AIS обычным браузером

Откройте [AIS Казахстан](https://ais.usvisa-info.com/ru-kz/niv). Прямой путь формы входа, используемый приложением: [вход в AIS](https://ais.usvisa-info.com/ru-kz/niv/users/sign_in).

Войдите со своими данными. Если кабинет еще не создан, создайте его штатным способом на портале и выполните необходимые для своего случая шаги. Монитор не заменяет эту процедуру.

Откройте действие записи или изменения даты собеседования. В зависимости от состояния вашего кабинета названия разделов могут различаться. Для получения адресов не подтверждайте новую запись и не отменяйте существующую.

### 7.2. Найдите schedule ID

На нужной странице адрес должен иметь вид:

```text
https://ais.usvisa-info.com/ru-kz/niv/schedule/YOUR_SCHEDULE_ID/appointment
```

`YOUR_SCHEDULE_ID` обозначает числовой номер из **вашего** URL. Он находится между `/schedule/` и `/appointment`. Это не номер паспорта, не номер анкеты DS-160, не ID города и не пароль.

Скопируйте полный адрес из строки браузера. Если там `/users/sign_in`, вы еще на форме входа. Если там главная страница без `/schedule/`, нужная страница пока не открыта.

Поддерживаются префиксы `ru-kz` и `en-kz`. Они означают язык интерфейса для Казахстана. Другие страны и режим `/iv/` этой версией приложения не поддерживаются.

### 7.3. Получите адрес списка дат

На странице записи выберите **Астана**. В Chrome или Chromium откройте инструменты разработчика:

- macOS: `Option + Command + I`;
- Linux/Windows: `F12` или `Ctrl + Shift + I`.

Затем:

1. Выберите вкладку **Network**.
2. Убедитесь, что запись сетевых запросов включена.
3. При необходимости выберите фильтр **Fetch/XHR**.
4. В строке фильтра введите `days/134.json`.
5. Обновите страницу записи или повторно выберите Астану, чтобы браузер запросил даты.
6. Откройте найденный запрос.
7. Во вкладке **Headers**, блоке **General**, скопируйте **Request URL**.

Ожидаемый формат:

```text
https://ais.usvisa-info.com/ru-kz/niv/schedule/YOUR_SCHEDULE_ID/appointment/days/134.json?appointments[expedite]=false
```

Это значение для `Dates API URL`. Число `134` относится к Астане; оно не меняется на ваш `schedule ID`. Query-параметр `appointments[expedite]=false` сохраните.

Если запрос не появился, сначала проверьте, что открыта именно страница выбора собеседования и выбрана Астана. Не используйте ID другого города как замену.

### 7.4. Получите адрес списка времени

В фильтре **Network** введите `times/134.json`. Если в календаре есть доступная дата, выберите ее, не нажимая окончательную кнопку записи. Откройте появившийся запрос и скопируйте его **Request URL**.

Браузерный запрос может содержать `?date=...` и другие параметры. Для поля приложения оставьте базовый адрес без `?` и query-параметров:

```text
https://ais.usvisa-info.com/ru-kz/niv/schedule/YOUR_SCHEDULE_ID/appointment/times/134.json
```

Монитор сам добавит дату и `appointments[expedite]=false` при запросе. Если свободных дат нет и запрос времени не возникает, базовый URL можно составить по этому формату из своего подтвержденного `Appointment URL`; его фактическая доступность проверится при появлении даты.

### 7.5. Сверьте три адреса

| Поле | Что должно находиться в конце |
| --- | --- |
| `Appointment URL` | `/schedule/ВАШ_ID/appointment` |
| `Dates API URL` | `/schedule/ВАШ_ID/appointment/days/134.json?appointments[expedite]=false` |
| `Times API URL` | `/schedule/ВАШ_ID/appointment/times/134.json` |

Во всех трех адресах должен быть один и тот же `schedule ID`. Вставлять `YOUR_SCHEDULE_ID` буквально нельзя. Адреса с чужим номером не подходят, даже если их структура выглядит правильно.

Копируйте только **Request URL**. Команда **Copy as cURL**, файлы HAR и полные HTTP-заголовки могут содержать cookies и данные авторизации: они не нужны для заполнения URL и не должны попадать в публичные обращения.

## 8. Запустите локальную панель

В активированном окружении выполните:

```bash
python src/web_app.py
```

Оставьте терминал открытым. В браузере откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Войдите с email и паролем администратора из `.env`.

`127.0.0.1` означает компьютер, на котором открыт браузер. Если сервис запущен на другом сервере, этот адрес сам по себе к серверу не подключит. Для сервера используйте SSH-туннель из раздела 15.

**Демо доступ** показывает синтетические результаты. Он нужен, чтобы посмотреть интерфейс, и не подтверждает, что ваш аккаунт подключен или мониторинг работает.

## 9. Заполните настройки пользователя

Для личного использования удобнее настроить профиль администратора:

1. Откройте вкладку **Пользователи**.
2. Найдите строку с email администратора.
3. Нажмите **Настройки** в этой строке.
4. Заполните данные из таблицы.
5. Нажмите **Сохранить настройки**.

| Поле в панели | Что ввести | Где взять |
| --- | --- | --- |
| Логин посольства | Email AIS | Ваш обычный вход на AIS |
| Новый пароль | Пароль AIS | Ваш менеджер паролей или сохраненный пароль аккаунта |
| Город | Астана | Единственный поддерживаемый вариант |
| Proxy URL | Обычно оставить пустым | Только адрес вашего работающего proxy, если он нужен |
| Appointment URL | Полный адрес страницы записи | Адресная строка AIS, раздел 7.2 |
| Dates API URL | URL `days/134.json` с query-параметром | Network, раздел 7.3 |
| Times API URL | URL `times/134.json` без query | Network, раздел 7.4 |
| Дней на подготовку | Сколько дней должно оставаться до собеседования | Вы определяете сами |
| Игнор-лист | Нежелательные даты или периоды | Ваши ограничения |
| Приоритетный список | Даты или периоды, на которые разрешена автозапись | Ваше явное решение включить запись |

При повторном редактировании администратором пустое поле **Новый пароль** сохраняет уже заданный пароль AIS. Не вставляйте туда пароль локальной панели.

Для первого подключения оставьте **приоритетный список пустым**, а proxy выключенным. Это позволит проверить мониторинг без попытки изменить запись.

Во вкладке **Личный кабинет** можно изменить логин, пароль и город собственного профиля. Полные индивидуальные URL настраиваются администратором во вкладке **Пользователи**. Отдельная вкладка **Астана** содержит общие URL; при нескольких аккаунтах индивидуальные адреса каждого пользователя должны быть заполнены, иначе общий URL может принадлежать другому аккаунту.

## 10. Первая авторизация и одна проверка

В верхней панели нажмите **Открыть логин**. Эта кнопка работает с профилем текущего администратора. Если фоновый мониторинг был запущен, приложение остановит его перед входом.

Скрипт:

1. Запустит установленный Chromium.
2. Откроет форму входа AIS.
3. Введет настроенные email и пароль, если появилась форма.
4. Откроет вашу страницу записи.
5. Выберет Астану и соберет данные сессии.
6. Сохранит сессию локально.
7. Сразу выполнит одну проверку дат и времени.

Следите за вкладкой **Логи запуска**. Код не решает CAPTCHA и MFA. При дополнительной проверке остановите повторные попытки и выполните ее обычным способом в разрешенном браузере. Автоматизация может завершиться по таймауту, поэтому не рассчитывайте на неограниченное ожидание ручного действия.

После входа можно нажать **Запустить проверку**. Проверка использует сохраненную сессию. Если журнал сообщает, что следующая проверка еще не наступила, это работа интервального ограничения, а не зависание. Дождитесь указанного времени или воспользуйтесь кнопкой сброса времени следующей проверки, если она доступна в панели.

Признаки корректного подключения:

- нет ошибки о незаполненных адресах или пароле;
- журнал показывает успешное получение данных;
- результаты относятся к Астане;
- пустой ответ отражается как отсутствие доступных дат, а не как подтвержденная запись;
- при перезагрузке панели настройки профиля остаются сохраненными.

Успешный вход не гарантирует наличие свободных дат. Появление даты не гарантирует, что на нее доступно время. Подтвержденную запись проверяйте в своем кабинете AIS.

## 11. Включите постоянный мониторинг

Во вкладке **Пользователи** установите нужному аккаунту статус **поиск включен**. Затем нажмите **Старт 24/7**.

Новый зарегистрированный пользователь получает статус **не оплачен**. В этой версии это локальная метка допуска к поиску; платежной системы в проекте нет. Администратор вручную меняет статус на **поиск включен** после настройки аккаунта.

По умолчанию веб-процесс проверяет, пора ли запускать монитор, каждые 30 секунд. Реальные запросы к AIS ограничены отдельным интервалом 60-300 секунд. Поэтому `USVISA_MONITOR_LOOP_SECONDS=30` не означает запрос к AIS строго каждые 30 секунд.

На macOS параметр `USVISA_WEB_PREVENT_SLEEP=true` включает `caffeinate` во время фонового мониторинга. Это не заменяет питание и не гарантирует работу ноутбука после закрытия крышки.

Для остановки поиска нажмите **Стоп 24/7**. Для остановки самого сервера нажмите `Ctrl+C` в его терминале. Если закрыть терминал или завершить Python-процесс, веб-панель и мониторинг прекратят работу.

Автоматический старт при запуске панели включается параметром **Стартовать мониторинг вместе с веб-панелью**. Включайте его в настройках панели после успешной ручной проверки; настройки панели сохраняются в SQLite и могут иметь приоритет над старым значением `.env`.

## 12. Как работает автоматическая запись

Приоритетные даты разрешают программе отправлять реальные запросы записи. Это относится и к браузерному логину: после него выполняется проверка, которая может перейти к автозаписи, если приоритеты уже заданы.

Чтобы включить автозапись:

1. Убедитесь, что обычный мониторинг работает с вашим аккаунтом и вашим `schedule ID`.
2. Проверьте текущую запись и правила ее изменения в AIS.
3. Задайте только те даты или периоды, на которые действительно согласны записаться.
4. Укажите время на подготовку в днях.
5. Убедитесь, что эти даты не исключены игнор-листом.
6. Сохраните настройки и включите поиск.

Не добавляйте широкий период просто «для проверки». При найденном подходящем слоте код пытается отправить запрос записи; при необходимости использует браузерный сценарий.

После подтвержденного успеха результат отображается в панели и журнале, а поиск для пользователя останавливается. Внешнего уведомления на email или в мессенджер не будет. Откройте AIS и самостоятельно проверьте дату, время и подтверждение. Если требуется дальнейший поиск, сначала проверьте фактическое состояние записи и только потом меняйте статус пользователя.

## 13. Если нужен только запуск из терминала

Без веб-панели заполните в `.env`:

```dotenv
USVISA_LOGIN_EMAIL=
USVISA_LOGIN_PASSWORD=
USVISA_APPOINTMENT_URL=
USVISA_DATES_API_URL=
USVISA_TIMES_API_URL=
USVISA_PRIORITY_DATES=
USVISA_IGNORED_DATES=
USVISA_PREPARATION_DAYS=3
USVISA_BROWSER_HEADLESS=false
```

Впишите собственные данные и адреса из раздела 7. Формат списков дат: `YYYY-MM-DD,YYYY-MM-DD`. Пустой `USVISA_PRIORITY_DATES` отключает автоматический выбор приоритетной даты для записи.

Войти и выполнить одну проверку:

```bash
python src/usvisa_browser_login_and_run.py
```

Позже выполнить одну проверку с сохраненной сессией:

```bash
python src/usvisa_appointment_monitor.py
```

Вторая команда не создает бесконечный цикл. Она проверяет `next_check_at`, при необходимости делает запрос и завершает работу. Для постоянного поиска используйте веб-панель.

Если вы уже настраивали веб-панель, CLI может взять данные администратора из SQLite, а не из измененного `.env`. Не смешивайте способы настройки одного аккаунта: для существующей панели редактируйте профиль через нее. Для отдельного CLI-сценария используйте отдельный каталог установки со своим `.env` и `state/`.

### Cookie, CSRF, Session-Id и ETag

Для обычной установки вручную собирать их не требуется. Браузерный вход получает и сохраняет рабочую сессию сам.

Если вы понимаете устройство HTTP-сессии и настраиваете bootstrap вручную, источником является **ваш авторизованный запрос** к AIS в DevTools > Network > Headers:

| Поле проекта | Где искать | Обязательно ли вручную |
| --- | --- | --- |
| `USVISA_BOOTSTRAP_COOKIE` | Request Headers > `Cookie` | Нет, обычно сохраняется браузерным входом |
| `USVISA_BOOTSTRAP_CSRF_TOKEN` | Request Headers > `X-Csrf-Token`; также meta `csrf-token` страницы записи | Нет |
| `USVISA_BOOTSTRAP_SESSION_ID` | Заголовок `Session-Id`, если он есть | Нет; отсутствующее значение не придумывать |
| `USVISA_BOOTSTRAP_IF_NONE_MATCH` | `If-None-Match` запроса или `ETag` ответа | Нет; это параметр кеширования |
| `USVISA_PREFER_BOOTSTRAP_SESSION` | Не берется с сайта: это переключатель приложения | Оставить `false`, чтобы использовать последнюю сохраненную сессию |

Cookie и CSRF должны относиться к одному аккаунту и совместимой сессии. Они могут истечь. Не берите их из чужого примера и не публикуйте. Вставлять такие значения можно только в свой приватный `.env` или соответствующие секретные поля локальной панели.

## 15. Постоянная работа на сервере Linux

Этот раздел описывает пример самостоятельного развертывания под обычным пользователем с SSH-доступом. Серверное окружение, firewall и доступность AIS необходимо проверить отдельно. Команды ниже не устанавливают reverse proxy и не открывают панель в интернет.

### 15.1. Установите проект на сервере

Подключитесь по SSH. Создайте каталог `~/usvisa-open-source` и выполните шаги установки из разделов 3-6 под тем пользователем, который будет запускать сервис. Для systemd-примера ниже каталог должен называться именно так.

На сервере без графического рабочего стола задайте:

```dotenv
USVISA_BROWSER_HEADLESS=true
USVISA_WEB_PREVENT_SLEEP=false
USVISA_MONITOR_AUTOSTART=false
```

Установите браузер и его Linux-зависимости. До создания службы запустите панель обычной командой и убедитесь, что она стартует без ошибок:

```bash
.venv/bin/python src/web_app.py
```

### 15.2. Откройте панель через SSH-туннель

В отдельном терминале на **своем компьютере**, заменив `SERVER_USER` и `SERVER_HOST` своими значениями:

```bash
ssh -N -L 8765:127.0.0.1:8765 SERVER_USER@SERVER_HOST
```

Теперь [http://127.0.0.1:8765](http://127.0.0.1:8765) в браузере компьютера будет вести к панели на сервере. Терминал с туннелем должен оставаться открытым. Если локальный порт занят, используйте `-L 8876:127.0.0.1:8765` и откройте локальный порт `8876`.

Не открывайте порт 8765 в публичном firewall и не меняйте bind-адрес на `0.0.0.0` ради первого запуска. Пароли и сессии защищает SSH-туннель. Для публичного многопользовательского размещения нужны отдельная оценка безопасности и серверная конфигурация, которых этот пример не предоставляет.

### 15.3. Создайте пользовательскую службу systemd

Сначала завершите ручной экземпляр панели через `Ctrl+C`, чтобы два процесса не использовали один порт и одну базу.

Создайте каталог и файл:

```bash
mkdir -p ~/.config/systemd/user
nano ~/.config/systemd/user/usvisa-open-source.service
```

Содержимое файла:

```ini
[Unit]
Description=US Visa Open Source local dashboard
After=network.target

[Service]
Type=simple
WorkingDirectory=%h/usvisa-open-source
ExecStart=%h/usvisa-open-source/.venv/bin/python %h/usvisa-open-source/src/web_app.py
Environment=PYTHONUNBUFFERED=1
UMask=0077
Restart=on-failure
RestartSec=30

[Install]
WantedBy=default.target
```

`%h` обозначает домашний каталог пользователя службы. Служба запускает Python напрямую из `.venv`; активировать окружение командой `source` внутри unit-файла не нужно. `.env` приложение прочитает самостоятельно из каталога проекта.

Размещение пользовательских unit-файлов описано в [документации systemd](https://www.freedesktop.org/software/systemd/man/latest/systemd.unit.html).

Примените конфигурацию:

```bash
systemctl --user daemon-reload
systemctl --user enable --now usvisa-open-source.service
systemctl --user status usvisa-open-source.service
```

Чтобы пользовательская служба могла работать после выхода из SSH и запускаться после перезагрузки сервера, администратор сервера может включить lingering для этого пользователя:

```bash
sudo loginctl enable-linger "$USER"
```

Это изменение настройки сервера. Выполняйте его только для нужного служебного пользователя. Если `systemctl --user` сообщает об отсутствии пользовательской шины, подключитесь обычной SSH-сессией этого пользователя и проверьте, поддерживает ли среда пользовательский systemd.

### 15.4. Управляйте службой

```bash
# Посмотреть последние сообщения
journalctl --user -u usvisa-open-source.service -n 100 --no-pager

# Смотреть новые сообщения
journalctl --user -u usvisa-open-source.service -f

# Перезапустить после изменения настроек запуска
systemctl --user restart usvisa-open-source.service

# Остановить панель и мониторинг
systemctl --user stop usvisa-open-source.service
```

Запущенная служба не обязательно означает включенный поиск. Откройте панель через SSH-туннель, настройте аккаунт, проверьте вход, затем включите **Старт 24/7**. Если поиск должен возобновляться после перезапуска службы, включите автозапуск мониторинга в настройках панели.

## 16. Где хранятся данные и как сделать резервную копию

| Путь | Что хранится |
| --- | --- |
| `.env` | Первичные настройки и секреты |
| `state/usvisa_web.sqlite3` | Пользователи панели, хэши паролей панели, настройки, учетные данные AIS, сессии |
| `state/usvisa_seen_dates.json` | Состояние отдельного CLI-монитора |
| `state/playwright-profile/` | Браузерный профиль CLI |
| `state/users/<user_id>/` | Отдельные состояние, cookies, журнал попыток записи и браузерный профиль пользователя панели |
| `state/browser-debug/` | Диагностические HTML и изображения, которые могут содержать персональные данные |

Пароли панели хранятся как хэши. Учетные данные AIS и рабочие сессии не зашифрованы на уровне приложения. Защитите доступ к учетной записи ОС, каталогу проекта и резервным копиям.

Перед резервным копированием остановите службу либо ручной процесс панели. Не копируйте работающую SQLite-базу как обычный файл, если не используете специальный механизм SQLite backup.

Из каталога проекта после остановки:

```bash
umask 077
tar -czf ../usvisa-private-backup.tar.gz .env state
```

Укажите новое имя архива, если такой файл уже существует: команда с тем же именем перезапишет предыдущий архив. Архив содержит секреты. Храните его в приватном защищенном месте, не загружайте в GitHub и не отправляйте вместе с исходниками.

Для переноса восстановите `.env` и `state/` в отдельную остановленную установку, проверьте права доступа и заново установите зависимости и Chromium. Браузерный профиль между разными ОС может не переноситься корректно; будьте готовы повторить вход. Не заменяйте существующую базу другой установки без отдельной резервной копии.

## 17. Обновление приложения

Остановите мониторинг, сделайте резервную копию по разделу 16 и остановите веб-процесс. Затем из каталога Git-установки:

```bash
git status --short
git pull --ff-only
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
```

Если Git сообщает о конфликте или локальных правках, не используйте `reset --hard`. Сначала сохраните свои изменения и разберитесь с конфликтом. Файлы `.env` и `state/` не входят в Git и не должны публиковаться при обновлении.

После обновления запустите панель, проверьте свои настройки и выполните одну ручную проверку прежде, чем снова включать автозапись. Если меняются формат данных или зависимости, сначала прочитайте описание изменений; возврат старого кода без совместимой резервной копии базы может быть недостаточен.

## 18. Проверка установки без обращения к AIS

Из активированного окружения:

```bash
python -m unittest discover -s tests
python -m compileall -q src tests
```

Тесты используют временные аккаунты и локальный сервер. Они не выполняют реальную запись в AIS. Для браузерных сценариев нужен Chromium, установленный для используемой версии Playwright.

Такая проверка подтверждает работу локальных сценариев приложения. Реальная авторизация, доступность слотов и возможность записи зависят от вашего аккаунта, сети и текущего поведения AIS.

## 19. Если что-то не работает

| Симптом | Что проверить и сделать |
| --- | --- |
| `python3.12: command not found` | Python 3.12 не установлен или недоступен через PATH. Проверьте установку до создания `.venv` |
| `No module named aiohttp` или `dotenv` | Активировано ли нужное окружение; повторите `python -m pip install -r requirements.txt` |
| Playwright сообщает `Executable doesn't exist` | Выполните `python -m playwright install chromium` тем же Python и тем же пользователем |
| `Missing X server` или ошибка `DISPLAY` | На сервере без рабочего стола включите headless в настройках панели. Для видимого окна настройте графическую сессию |
| Ошибка `USVISA_ADMIN_EMAIL` или `USVISA_ADMIN_PASSWORD` | Заполните `.env`; пароль администратора должен быть не короче 12 символов |
| `Address already in use` | Уже запущена панель на этом порту; остановите второй экземпляр или задайте другой порт |
| Панель на сервере не открывается по `127.0.0.1` | Создан ли SSH-туннель на компьютере с браузером; выбран ли его локальный порт |
| Не видны административные вкладки | Вы вошли обычным пользователем или в демо. Используйте локального администратора |
| Настройка `.env` не меняет поведение панели | Сохраненные настройки и профиль в SQLite имеют приоритет. Меняйте существующую конфигурацию через панель |
| `Only Astana` или ошибка URL | Проверьте `kz`, `/niv/`, ID `134`, собственный числовой `schedule ID` и совпадение трех адресов |
| Логин выполняется не тем аккаунтом | Проверьте профиль текущего администратора; кнопка браузерного логина работает именно с ним |
| `401`, `403` или переход на форму входа | Сессия истекла либо сайт отклонил запрос. Остановите повторные попытки, проверьте обычный вход и обновите браузерную сессию |
| `429 Too Many Requests` | Остановите мониторинг; следуйте ограничениям сайта и увеличьте интервалы перед повторным запуском |
| `502`, `503`, `504` | Возможна временная проблема AIS или сети. Проверьте обычный браузер и не увеличивайте частоту запросов |
| CAPTCHA или MFA | Выполните штатную ручную проверку; обхода в приложении нет |
| Дат нет | Это допустимый результат. Успешный пустой список не означает неисправность |
| Дата есть, времени нет | Доступность даты и конкретного времени проверяется отдельно; запись пока может быть невозможна |
| «Следующая проверка еще не наступила» | Действует сохраненный интервал `next_check_at`; дождитесь времени следующей проверки |
| Аккаунт пропускается в 24/7 | Нужны статус **поиск включен**, заполненные данные AIS и корректные URL |
| Второй аккаунт не идет параллельно | Параллельный режим требует отдельного proxy для каждого одновременно проверяемого аккаунта; не подставляйте фиктивный proxy |
| Автозапись не срабатывает | Проверьте приоритетные даты, игнор-лист, дни подготовки, наличие времени и ошибки конкретной попытки |
| Не пришло письмо или сообщение | В этой версии внешних уведомлений нет. Результат нужно смотреть в панели и AIS |

При обращении с ошибкой достаточно версии Python, ОС, команды запуска и очищенного текста ошибки. Не отправляйте `.env`, базу SQLite, cookies, пароль, полный HAR или HTML страницы своего кабинета.
